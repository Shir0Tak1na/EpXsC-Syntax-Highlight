# EpXsC Syntax Highlight

给 **EpXsC（述无空语构造记号 / Expaulxsirian Construct）** 代码块做真正的语法高亮。An Obsidian plugin + CSS snippet that turns ```EpXsC code blocks into properly coloured tokens.

```EpXsC
Expaste(METOS: a, METOS: b) {
	intervall(a, b) <= 66 miteas;
	luss (15 + 35 * intervall(a, b)) MU;
}
```

## 为什么光有 CSS 不够

Obsidian 的代码块只有在 Prism 认识那个语言时才会被切成 `<span class="token keyword">` 这类小片。`EpXsC` 不在 Prism 的语言表里，DOM 里就是一整块纯文本，而 CSS 没法按文本内容选元素。所以：

| 文件 | 职责 |
| :--- | :--- |
| `main.js` | 把 EpXsC 注册进 Prism（分词） |
| `styles.css` | token 配色与代码块外框（插件启用时自动加载） |
| `snippets/EpXsC-Highlight.css` | 同一套配色的独立片段，给只想用片段、不开插件的人 |

## 安装

1. 把 `main.js`、`manifest.json`、`styles.css` 放进 `<库>/.obsidian/plugins/epxsc-syntax/`
2. 设置 → 第三方插件 → 关闭受限模式 → 刷新 → 打开 **EpXsC Syntax**

`styles.css` 随插件自动加载，**不需要**再开 CSS 片段。

只要配色、不要插件：把 `snippets/EpXsC-Highlight.css` 放进 `<库>/.obsidian/snippets/`，在外观 → CSS 代码片段里启用 —— 但那样只有代码块外框，没有 token 着色。

## 四类名字怎么认出来的

| 类别 | 认法 | 颜色 |
| :--- | :--- | :--- |
| **术式名（声明）** | 大写开头且后面紧跟 `(` `{` `[`，或下划线复合名（`Gramakipo_Aepaus`） | 黄 `--epx-decl`（浅色主题自动压深） |
| **类型名** | ① 登记表 `TYPES`（`METOS`、`locus`）；② 参数表里紧跟 `(` 或 `,`、后面是冒号的词（`locus: zone` 的 `locus`）。用 Prism 的 lookbehind 写法实现，单字母按变量名放过 | 青 `--epx-type` |
| **元素码** | `ELEMENTS` 十种，大小写敏感 | 青（与类型同族） |
| **谓词 / 谓词调用** | 词典「动词」表，以及后面跟 `(` 的小写词 | 蓝 `--epx-verb` |

「类型: 变量名」的写法里**变量名不着色**（类型在前，如 `locus: zone`）。`构思案/_术式语法_粘贴原文.md` 里那几块是旧写法（`zone: locus`），会反过来着色，属正常。

## token 类名与配色

类名：`comment annotation pretium keyword predicate function declaration element type unit number degree axis pointer operator paren bracket brace punctuation rankRange`。参数表里的类型位会输出两个类（`token typeParam type`），走 `.token.type` 的样式。

**括号按种类分了三类**：`()` → `paren`，`[]` → `bracket`（列表 ／ 下标 ／ **秩**），`{}` → `brace`（语块）——对应语法里的「容器类型由括号自己声明」。

**秩区间**：`1..3`、`..10`、`2..` 这类由 `rankRange` 单独着色（默认橙、加粗、虚线下划线）。模式要求至少一边有数字，所以省略号 `...` 不会被吃掉，仍归 `operator`。

**嵌套括号**：Prism 是逐位置的词法分析、数不了层数，所以 `main.js` 里的 `markBracketDepth()` 在它产出 HTML 之后再扫一遍，给每个括号补上 `epx-d1` / `epx-d2` / `epx-d3`（三层一循环，再深轮回第一层）。第 1 层保持分类色（`[` 青、`()` 淡、`{}` 略亮），**第 2 层起才换色**（`--epx-b2` 品红、`--epx-b3` 绿），既不吵又能对上号：

| 写法 | 层数反映 |
| :--- | :--- |
| `ExpasteZone(METOS: [2:metos])` | `(` d1，`[` d2 —— 内层的秩方括号被顶出来 |
| `luss (15 + 35 * intervall(a, b)) MU;` | 外层 `(` d1，`intervall(` 的 `(` d2 |
| `(*x1)[1..3] = x2;` | `(` d1 先闭合，`[1..3]` 回到 d1 |

不想要嵌套换色：把 `styles.css` 末尾 `.epx-d2` / `.epx-d3` 两条删掉即可（`epx-d*` 类照旧生成，只是没有色差）。
## 悬停提示（像 IDE 那样）

鼠标停在**任何一个** token 上都会浮出一张卡片：类名 ＋ 解释。全库 55 个 EpXsC 代码块里，1666 个 token 中 97% 以上有内容可讲。

| 悬停对象 | 显示 |
| :--- | :--- |
| `plur` | 谓词（缩写 PLU）· 净化 |
| `Purificatio` | 术式名 · 本术式的声明名 |
| `locus`（类型位） | 类型名（缩写 LOCs）· 地点、位置 |
| **`zone`**（形参） | **变量 zone · 形参，声明为 locus（名词 地点、位置）；作用域到块末** |
| **`x1`**（赋值绑定，`x1 = &metos[1]`） | **变量 x1 · 是个地址 —— & 取得的引用；设定里地址本身就是位置（第 1–3 秩）** |
| `(` 在术式名后 | 圆括号 · 参数表 —— 写法「类型: 变量名」，逗号分隔，类型可省 |
| `(` 在谓词后 | 圆括号 · 实参表 |
| `(` 其余 | 圆括号 · 分组／元组 |
| `[` 含 `=` | 方括号 · 筛选键表 —— `genus` 类别、`intervall` 距离、`ordin` 排序、`limit` 取前几个… |
| `[` 含 `:` | 方括号 · 列表类型（`[:METOS]` 是「一列目标」） |
| `[` 形如 `2:x` | 方括号 · 位数：变量 |
| `[` 含 `&` | 方括号 · 点名列表 |
| `[` 含 `siro` / `*` | 方括号 · 目标集 |
| `[` 含 `..` 或单个数 | 方括号 · 下标（秩） |
| `{` | 花括号 · 语块（同一形状兼作字典／映射） |
| `1..3` | 秩 1–3 · x, y, z · 三维空间元组（第三维度，占 3 秩） |
| `MU` | 单位 · 魔力（能量）；写它即为锁存（触发式术式） |
| `MUW` | 单位 · 能量单位 魔力功率；功率口径，不得配 luss（持续发动） |
| `miteas` / `passus` / `hora` … | 单位 · 长度 米 ／ 长度（旧制）步 ／ 时间 小时 |
| `?` | 占位符 · 自适应参数：值在发动时绑定（由施术者指定，或由术式自适配） |
| `^` / `~` | 局部坐标（受术者三轴）／ 相对坐标（世界轴） |
| `&` / `*` / `@` | 取地址 ／ 解引用 ／ 目标简写 |
| `=` / `+=` / `<=` / `..` | 赋值 ／ 复合算子 ／ 比较 ／ 区间 |
| `;` `,` `:` | 子句分隔 ／ 并列 ／ 下一层开始 |
| `/* … */` | 注释（`//` 不用——`/` 在术式里是相变） |
| 词典里没有的词 | 未入典 · 写进《述无空语词典》后着色与释义会自动跟上 |
| 裸词根（如 `flagro`） | 词根·动 · 燃炽 |

变量的类别有两个来源：**形参**看参数表里的「类型: 变量名」；**赋值绑定**看 `=` 右侧的写法 —— `&…` 地址、`*&…` 那物本身、`@…`／`METOS[…]` 对象集、`[…]` 列表、`(…)` 元组、`{…}` 字典、数字开头数值、谓词调用结果、元素码或类型名则是其本身；已知变量标「同源」，判不出来的如实标「未定」。`(*x1)[1..3] = x2`、`radius *= 2`、`<= 66` 这类不是声明，不会被误认。

> 文案原则：**只给类别与释义，不举例子**。类别按「小节 → 词性」映射取真词性（`urb` 显示「补充词」而不是小节名「高频补充词」）。

数据全部在库内，改文件即改提示：

1. `述无空语词典.md` —— 词性（取所在小节）＋ 释义 ＋ 缩写，约 500 条
2. `述无空语术式语法.md` —— 「筛选键」10 个 ＋ 「六、单位」两张表（MU / EU / MUW / EUW 与 passus · sands 等，按并列顺序与量名一一配对）
3. `维度模型.md` —— 「九个秩与维度的对应」，`1..3` 走单行、`7..9` 由单秩合成

浮层用 `position: fixed` 挂在 `body` 上，不会被代码块的 `overflow` 裁掉；样式在 `styles.css` 第 5 节（`.epx-tip`）。

**两种视图都可用**：阅读视图按 token 取类别；实时预览里代码块不是 Prism 渲染的（没有 token），改为取光标下的那个词直接查词典。

**自检**：命令面板搜「EpXsC 悬停自检」——显示词典/秩表条数、当前视图、本页代码块数量与其中带 token 的数量。

**边界**：移动端没有 hover；实时预览里拿不到「变量→类型」的块内信息（那条要 token）。

## 自带词库（别人下载后不用任何文件也能用）

插件内置一份词库快照（`main.js` 末尾的 `BUILTIN_LEXICON`）：

| 内容 | 条数 |
| :--- | ---: |
| 词典词条（词性／释义／缩写） | 475 |
| 筛选键 | 10 |
| 单位（MU / EU / MUW / EUW ＋ passus · sands …） | 14 |
| 秩的构成 | 7 |
| 词根（带根类：动／物／性／数） | 5231 |
| **合计** | **5737 条，约 163KB** |

**优先级：库内文件 > 内置快照。** 库里找得到那三份文件就用文件（所以改词典立刻生效），找不到（别人下载的库）就用快照 —— 两条路的行为已核对为一致。

词根表按**整个目录**读（`词库/词根表/`），新增或重切分册会自动纳入；目录不存在时才吃快照。动-根同时进谓词表，所以 `flagro`、`sec`、`tritur` 这些裸根在代码里按谓词着色。

**不带** `词库/词表/*`（26 册、16.7MB 的生成词形）：插件不读它，也没有必要——真要用时把词补进词典即可。

**刷新快照**：快照是某一天的切片，对你自己没影响（文件优先）；要更新给别人用的那份，说一声我重新生成一次即可（生成用的解析器与运行时完全同一套）。

## 语法检查

命令面板 → **「检查当前笔记的 EpXsC 代码块」**。结果出一个面板：几个块、几处问题（错误／警告各几处），**点一行跳到那一处**。

| 检查项 | 级别 |
| :--- | :--- |
| 括号：多一个、少一个、交叉（`([)]`）、未闭合 | 错误 |
| 冒号开的块，块体不比块头更深 | 错误 |
| `luss` 与 `MUW`／`EUW` 同用（功率口径不得写锁存） | 错误 |
| 判断词（`keal`／`keol`／`tam`／`dum`／`nisi`／`quan`）没带块 | 警告 |
| 数字后面跟的词不是登记过的单位 | 警告 |
| `lic magis`／`lic minus` 那一行没有 `?` | 警告 |
| 筛选键不在登记表里 | 警告 |
| 下标（秩）超出 1–9 | 警告 |

**日常句不算术式**：块里只要有一行以句号收尾，整块按日常句对待，只查括号，不套术式的规矩 —— 这正是文档里「`.` 不参与术式」那条分界。

词典里查不到的词（≥4 个字母、不含数字）会加一条**橙色点线**（未入典）；不想要就删掉 `styles.css` 第 6 节里的 `.epx-unknown` 那一条。

> 全库 55 个 EpXsC 块跑下来报 17 处，全部落在旧稿上（冒号开的块没缩进）—— 按文档规矩是真问题，不是误报。

## 词表更新如何适配

- 听**三份文件**的 `modify` 事件：`述无空语词典.md`、`述无空语术式语法.md`、`维度模型.md`。改动其中任何一份，插件会自动重读并重渲染，不用重启。
- 也可以手动触发：命令面板 → **「重新载入词表与释义」**。
- 新词只要写进词典，**着色与释义同时跟上**；只改了释义、没改词表，也一样生效。
- **不覆盖的**：`词库/词根表/*` 与 `词库/词表/*` 那些分册（26 册 × 上千条，逐个读会拖慢启动）。只在这两处出现、词典里没有的词，会显示「未入典」——把它补进词典即可。
- 词表来源小节可在 `main.js` 的 `SECTIONS` 常量里增删；类型登记表是 `TYPES`，元素码是 `ELEMENTS`。
## 启动时序与自愈

Obsidian 启动时，首屏可能在社区插件加载完成**之前**就已渲染（那一次不经过插件的 markdown 后处理器），`window.Prism` 也可能尚未就绪。插件因此带一层自愈，不必手动切笔记：

- 载入后 0.4s / 1.5s 各补一次
- `layout-change`、`active-leaf-change` 时补
- 每 2.5s 的看门狗：确认「EpXsC 语法仍在 `Prism.languages` 里」且「页面上每个 EpXsC 代码块都有 token」，缺哪个补哪个

## 已知边界

- **阅读视图 / PDF 导出**：完整高亮。
- **实时预览（编辑态）**：Obsidian 编辑器走 CodeMirror 自己的解析器、不读 Prism，所以只有代码块外观、没有 token 着色。按 Ctrl+E 切到阅读视图即可见。
- 外框与右上角语言签用了 CSS `:has()`，需要 iOS 15.4+ / 较新的 Chromium；不满足时只是外框与语言签不出现，token 着色不受影响。
- 词表依赖上表那份词典笔记；换库或改路径请同步改 `main.js` 里的 `DICT_PATH`。
